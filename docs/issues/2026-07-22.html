Gemini 3.6 Flash — 复杂任务主力
🏆 Google 称之为「workhorse model」· 7月22日凌晨发布
🏆 主力模型💎 输出Token直降17%🔥 今天就能用
是什么：Google 称为 「workhorse model」——承担日常复杂工作的主力模型。在 3.5 Flash 基础上升级，强化代码、知识工作、多模态理解和计算机操作能力。
核心指标是Token效率：综合评估平均消耗 Token 从 28K 降至 23K（降 17%）；DeepSWE v1.1 编码长任务从 276K 降至 97K（降 65%）。同样的活更少花钱。
最适合：日常复杂分析、编码任务、长文档处理——凡是「要认真干」的活都交给它。
🎯 今天就能试：把手上最复杂的一个分析任务（比如一份 50 页研报的拆解）丢给 3.6 Flash，对比 3.5 Flash 的 Token 消耗，直观感受「同样的活更省」。

Gemini 3.5 Flash-Lite — 高并发跑量
⚡ 轻量模型 · 面向高并发流水线
⚡ 轻量跑量📈 高并发💰 成本敏感
是什么：面向高并发流水线场景的轻量模型，适合大批量、低延迟、成本敏感任务。和主力模型配合使用——重要活给 3.6 Flash，批量活给 Flash-Lite，分工明确、账本清晰。
最适合：批量文本处理、海量摘要、数据清洗、内容打标——任何「量大但单条不复杂」的流水线任务。

安装后在 Codex 中即可调用 Flash-Lite 跑批量任务
🎯 今天就能试：把批量文本处理任务（比如 100 篇新闻摘要）交给 Flash-Lite 跑流水线，观察单条成本与整体耗时。

Cursor 树状分层多智能体 — 4小时写出一款数据库
🔥 7月22日公开实验 · 依托 Grok 4.5
🔥 突破实验🕸️ 树状架构📚 Rust
是什么：Cursor 公开实验：依托 Grok 4.5 搭建树状分层代理集群，仅 4 小时从零开发出兼容 SQLite 标准的 Rust 数据库 minisqlite，通过 80% 官方标准 SQL 测试。
架构亮点：采用「规划者+执行者」双层树状架构——顶层递归拆分任务树，底层独立执行细小子任务，内存完全隔离。
意义：单个 LLM 的产出有天花板，但一群分工的智能体可以像小型工程团队一样作战。
🎯 今天就能试：把一个「大而模糊」的任务（比如「做一个个人博客系统」），手动拆成顶层 5 个子任务、每层再拆叶子任务，交给 Cursor 分层执行，感受树状分工带来的稳定性。

实用技巧
🧮 怎么看模型性价比——别只看参数，盯Token效率
参数越大不等于越省。真正的省钱指标是：同样的任务，消耗的 Token 降多少。Gemini 3.6 Flash 综合评估 Token 消耗降 17%、编码长任务降 65%——这就是「同样的活更少花钱」的量化表达。实操：选模型前，先拿一个你真实的任务跑一遍，对比新旧版本的 Token 账单，数字不会骗人。
🌳 树状分层思路可迁移到个人工作流
Cursor 用「规划者+执行者」树状架构 4 小时写出数据库——这套思路完全适用于个人工作流：复杂任务拆顶层、简单子任务派发。比如「整理 Q3 数据报告」：顶层拆成「数据拉取→指标计算→图表制作→成稿润色」，每个叶子任务交给最合适的模型/工具去执行，内存隔离、互不干扰。一个人也可以是一支团队。
